Instruction definition

The 16-bit instruction set and the six host commands that load it. The readable form of the same programs is in docs/machine_definition.html. The protocol facts those programs have to cover are in docs/protocol_model.md.

Machine state

Two groups of registers. The host fills the first group while the machine is stopped. The run owns the second group.

NameWidthWho writes itWhat it is
imem2 banks of 32 words, 16 bits eachHost, through the load mapThe program. The engine reads the active bank. One word is one run step. The program counter is 5 bits. While running, stores go to the other bank.
T, Tlo, Thi16 bits eachHostThe three hold lengths a step can name. T/2 is T shifted right by 1, not a fourth register.
roles 0–3, sideone byte eachHostWhich physical pin each role uses, how it is driven, and the idle level it sits at during load.
out_dir, in_dir, xreloadone byte togetherHostBit order of the two shift registers, and the value setx loads into x.
output shift8 bitsHost, once per frameThe payload byte to send.
pc5 bitsHost at the start of a run, then the sequencerThe address of the next instruction.
input shift8 bitsThe run, then the host reads itThe byte assembled from sampled pins.
x4 bitsThe runThe loop counter. setx loads xreload. xdec subtracts 1.
wait_left16 bitsThe runTicks remaining in the current hold.
running1 bitHost sets it, OP_HALT clears it1 while a program is executing. Config writes are ignored while it is 1, except byte 0x4D. FIFO push and pop are not. An armed OP_HALT switches banks and leaves this set.

A period of 0 is stored as a hold of 1, so a pin always spends at least one tick at a new level. Reset, and every tick of the load phase, leaves each bound pin at its idle level.

Host interface

The host writes one config field per tick while running is 0. On that tick it presents three values: a strobe, a command, and a data byte. CMD_PUSH and CMD_POP are also accepted while running is 1.

PinsRole
ui[0]Write strobe. 1 for exactly one tick, then 0.
ui[3:1]Command number. Three bits, eight slots. Six are used.
uio[7:0]Data byte for that command. A push or pop during a run uses this byte too, so a protocol that lives on uio cannot take one mid-transfer.
 
localparam [2:0] CMD_ADDR    = 3'd0;  // set the load address
localparam [2:0] CMD_WRITE   = 3'd1;  // store one byte there, then address + 1
localparam [2:0] CMD_PAYLOAD = 3'd2;  // output shift register
localparam [2:0] CMD_PC      = 3'd3;  // first instruction of this run
localparam [2:0] CMD_RUN     = 3'd4;  // running = 1, data ignored
localparam [2:0] CMD_READ    = 3'd5;  // stopped: input shift. running: FIFO status
localparam [2:0] CMD_PUSH    = 3'd6;  // enqueue one TX FIFO byte
localparam [2:0] CMD_POP     = 3'd7;  // dequeue one RX FIFO byte onto uio

A tick with the strobe at 0 changes nothing. A tick with the strobe at 1 while running is 1 ignores CMD_PAYLOAD, CMD_PC, and CMD_RUN. CMD_ADDR and CMD_WRITE still run, and an instruction-memory store lands in the bank that is not executing. CMD_PUSH, CMD_POP, and CMD_READ are accepted too. CMD_READ while stopped drives the input shift. While running it drives the FIFO status byte. CMD_POP drives the oldest RX byte, or 0x00 if the FIFO is empty.

Each of those three turns uio into an output for that one tick. Every other tick leaves those pins as the program left them.

The instruction at pc executes on the tick after the write that sets running. That write itself is still a load tick.

The other way to expose the same fields is one command number each, with no address register: three wait registers as six byte writes, five pin bindings, the direction byte, an instruction-memory pointer, an instruction-memory write, the payload, the program counter, run, and read. That is sixteen commands. Sixteen needs ui[4:1]. The six-command map keeps the three-bit field and puts the twelve config bytes behind CMD_ADDR and CMD_WRITE, the same path the instruction words already use.

Load byte space

CMD_ADDR sets a byte address. Each CMD_WRITE stores the data byte there and adds 1. Instruction memory is the first 64 bytes, 32 words of one bank, low byte then high byte. The high byte commits the word. While the machine is stopped those bytes are the active bank. While it is running they are the other bank. Config is the bytes after that.

AddressField
0x00–0x3FOne bank of imem. Word n is bytes 2n and 2n+1, low then high. Stopped writes hit the active bank. Running writes hit the other.
0x40, 0x41T, low then high. UART's bit time. 5208 at 9600 baud, 434 at 115200.
0x42, 0x43Tlo, low then high. The low half of a clock this side generates.
0x44, 0x45Thi, low then high. The high half. SPI's fastest clock is Tlo = Thi = 1.
0x46–0x49Role 0 to role 3, one binding byte each.
0x4AThe side pin, same binding byte.
0x4BShift directions and the loop reload.
0x4CShift width and base pin. Left at reset, the width is one bit and the role pin is used.
0x4DBit 0 arms a bank switch. Bits [4:1] are yreload. The arm is taken on OP_HALT, or when pc steps off word 31 without a backward branch. The banks flip, pc is 0, and running stays 1.

A binding byte is {mode[1:0], idle, pin[4:0]}.

BitsFieldWhat it is
7:6mode0 input, 1 push-pull, 2 open-drain. 3 is unused.
5idleThe level the pin rests at during load and after reset. Push-pull: the driven level. Open-drain: 0 pulls, 1 releases. TX and CS idle at 1. SDA and SCL idle released. SCK idles at the mode's rest level.
4:0pin0–7 are ui, 8–15 are uo, 16–23 are uio.

Byte 0x4B is {out_dir, in_dir, autopull, autopush, xreload[3:0]}. Byte 0x4C is {0, width[1:0], base[4:0]}. Width 0 is one bit, 1 is two bits, 2 is four, 3 is eight. The low pin of the group is the low bit. Width 8 places the whole byte on eight consecutive pins. A group stays inside one port. Eight bits fit on uio or ui. Pin 15 is running, so they do not fit on uo.

BitsFieldWhat it is
7out_dir0 shifts bit 0 out first. 1 shifts bit 7 out first.
6in_dirThe same choice for the input shift. The first sample becomes bit 0 when this is 0, and bit 7 when it is 1.
5autopull1: the 8th shift of a byte loads the next TX FIFO byte. A looping branch with the FIFO empty holds the pins.
4autopush1: the 8th sample is copied into the RX FIFO. 0 leaves the one-byte machine.
3:0xreloadWhat setx loads into x. 8 for a data byte. 9 for a frame that loops a ninth bit.

Loading a protocol is CMD_ADDR 0x40 plus twelve writes, then CMD_ADDR 0x00 plus two writes per instruction word. Running a later frame of the same protocol is three ticks: CMD_PAYLOAD, CMD_PC, CMD_RUN. After a receiver or a full-duplex transfer stops, CMD_READ presents the assembled byte.

Opcodes

Eleven operations. Halt is 0, set is 2, shift is 3. The other high nibbles are wait, in, the two open-drain operations, hold, match, jmp, and xor.

localparam [3:0] OP_HALT    = 4'h0;  // running = 0. Pins stay.
localparam [3:0] OP_WAIT    = 4'h1;  // stall until role reads val
localparam [3:0] OP_SET     = 4'h2;  // drive role to val, push-pull
localparam [3:0] OP_SHIFT   = 4'h3;  // drive role to the next payload bit, push-pull
localparam [3:0] OP_IN      = 4'h4;  // sample role into the input shift
localparam [3:0] OP_OD      = 4'h5;  // pull or release role. val 0 pulls, val 1 releases
localparam [3:0] OP_ODSHIFT = 4'h6;  // payload bit 0 pulls role, bit 1 releases it
localparam [3:0] OP_HOLD    = 4'h7;  // change no pin, only load the wait
localparam [3:0] OP_MATCH   = 4'h8;  // stop unless the role reads val
localparam [3:0] OP_JMP     = 4'h9;  // branch on a condition. No pin write
localparam [3:0] OP_XOR     = 4'hA;  // width-1 differential bit. side is the complement

OP_SHIFT and OP_ODSHIFT consume one bit of the output shift. The bit taken is the one out_dir names. OP_IN assembles bits in the order in_dir names.

OP_JMP takes bits [9:7] as the condition: 0 always, 1 Y != 0, 2 Y == 0, 3 more payload. True and back != 0 goes to pc - back. True and back == 0 skips the next word. False advances one.

OP_XOR is width 1. val 0 drives level XOR ~bit and consumes the bit. val 1 toggles without taking a bit. side drives the complement. On this opcode xdec and setx touch Y, not X. CMD_RUN loads Y from yreload in 0x4D[4:1].

side is allowed on OP_SET, OP_SHIFT, OP_IN, OP_OD, OP_ODSHIFT, and OP_XOR. The data pin and the side pin update together, then the hold runs. A pin the word does not write keeps its level.

The 16-bit word

One word is one run step. Bits the step does not use are written as 0.

BitsFieldWhat it is
15:12opWhich operation. The constants are above.
11:10roleWhich data pin, a number from 0 to 3. The load map binds the number to a physical pin.
9valFor OP_SET, the level driven. For OP_WAIT, the level to wait for. For OP_OD, 0 pulls and 1 releases. For OP_ODSHIFT, 1 stops the run when an open-drain bus does not read back the bit just driven. How to read one word

SPI's sample step is 0x49BA.

0100 1001 1011 1010
op   role val side side_val hold xdec back setx
0100 10   0   1    1        011  1    01   0

Opcode 0100 is OP_IN. Role 10 is MISO, role 2. side is 1 and side_val is 1, so SCK is driven high on that same tick. hold is Thi. xdec is 1 and back is 1, so while x is still above 0 the next instruction is the previous one, which is the OP_SHIFT that presents the next MOSI bit.

What the set supports

The four programs below are made of these moves.

MoveHow
Shift outOP_SHIFT on a push-pull pin, OP_ODSHIFT on an open-drain pin, OP_XOR for a differential toggle. Either bit order, from out_dir.
Shift inOP_IN, eight bits, in the order in_dir names.
Two pins on one tickThe data role, plus the side pin when side is 1. SPI's clock beside MOSI. I2C's clock beside SDA. OP_XOR drives the complement on the side pin.
Six hold lengthsT, T/2, Tlo, Thi, one tick, or none. Tlo = Thi = 1 is a 25 MHz SPI clock.
A loop of N bitsCounter x. setx loads xreload. xdec with back 0 to 3 jumps backward while x stays above 0.
A run-length counterCounter Y and yreload. OP_XOR with xdec counts ones. OP_JMP branches on Y or on more payload.
StallOP_WAIT until a role reads 0 or 1. UART start edge, I2C clock stretch.
Pull and releaseOP_OD and OP_ODSHIFT. A 0 in the payload pulls. A 1 releases.
Halt with the pins heldOP_HALT clears running and leaves the last levels. A multi-byte I2C transfer continues from a later pc.

What it does not do:

MissingConsequence
No long forward jumpOP_JMP skips one word or jumps backward at most three. The host still stitches longer segments by writing pc.
No branch on the bit just sampledOP_MATCH, and OP_ODSHIFT with bit 9 set, halt when the wire disagrees. They do not select an address. A program that does not use them still leaves an I2C NACK for the host to read after halt.
Two pins per step, not threeJTAG's TCK, TMS, and TDI setup takes two ticks.
hold codes 6 and 7Reserved.

The required programs together fit in the 32-word bank. They can also replace each other: the host rewrites imem and the config bytes when the protocol changes. prog/usb_ls_tx.asm is a later program in the same word format: yreload is the stuff length, not a constant in the Verilog.

UART sender

Role 0 is TX, push-pull. No side pin. Shift bit 0 first. T is the bit time. Four words. The loop is one OP_SHIFT that jumps to itself.

UART receiver

A second program. Role 0 is RX, an input. The first sample becomes bit 0. The OP_WAIT tick is the start edge. The two holds after it are the rest of the start bit and half of bit 0. The stop bit is a second OP_WAIT, for 1. Sampling it with OP_IN would shift bit 0 out of the 8-bit input register. A stop level of 0 stalls on that instruction. After halt, CMD_READ presents the assembled byte.

SPI master

One program, mode 0. Role 0 is MOSI, role 1 is CS, role 2 is MISO. The side pin is SCK, push-pull, idle 0. Shift bit 7 first, out and in. CS is its own instruction, so the bit step writes two pins: MOSI and SCK, or MISO's sample and SCK.

AddressWordInstructionWhat the pins do
00x2421OP_SET CS, 0, hold Tlo, setxSelect the device. x = 8.
10x3120OP_SHIFT MOSI, side SCK 0, hold TloNext data bit, clock held low.
20x49BAOP_IN MISO, side SCK 1, hold Thi, xdec, back 1Clock rises and MISO is sampled on that tick. Then back to address 1.
30x2620OP_SET CS, 1, hold TloRelease the device.
40x0000OP_HALTThe input shift holds the byte that came in on MISO.

More than one slave is still on this ASIC. SCK, MOSI, and MISO stay shared. Each slave gets its own chip-select pin on this die. No off-chip CS demux is assumed. Role 1 is CS0 in the listing above. Role 3 is free for a second CS the program can OP_SET. Every further slave uses another uo or uio pin: the host drives that CS low before CMD_RUN and high after halt. Only one CS is low at a time. ui cannot be a CS. The bit loop is unchanged; the slave count is the leftover output pins after the three shared wires are placed.

I2C master

One program. Role 0 is SDA and role 1 is SCL, both open-drain. The side pin is SCL, so a data bit and the clock can change together. side_val 0 pulls SCL, and 1 releases it. The payload is the address byte, bit 7 first. Sixteen words. All four programs on this page are 31 words, which fills 32 slots of 16 bits minus one.

A second data byte repeats addresses 2 through 10. Halting after address 10 leaves SCL pulled, which holds the bus. Address 10 also reloads x, because the bit loop leaves it at 0. The host writes the next payload, sets the program counter to 2, and runs. Address 11, the stop, runs after the last byte.

Why 16 bits, not 8

The fields above add up to 16. Four are the opcode. The other twelve are what one SPI or I2C step has to say at once: which data pin, the level or the pull, whether the clock pin changes on that same tick, which wait to load, and whether the loop repeats.

FieldBitsWhy it is in the word
op4Eight operations. Three bits would also cover eight operations.
role2SPI touches MOSI, CS, and MISO. One configured data pin cannot name all three.
val1The driven level, the level to wait for, or pull versus release.
side, side_val2The clock beside the data. At one tick low and one tick high, this cannot be a later instruction.
hold3UART uses T and T/2. I2C uses Tlo, Thi, one tick, and no wait. One program needs more than one length.
xdec, back, setx4Eight data bits from one instruction. UART jumps to itself, SPI jumps back one, I2C jumps back three.

That is 4 + 12. Dropping the opcode to 3 bits and storing the loop target in a register instead of back still leaves about 12 bits. Twelve does not fit in a byte. Eight bits is the UART transmitter only: one pin, one hold length, and the eight shifts written out as eight bytes.

uio[7:0] stays 8 bits. Those pins are the load bus, used while the machine is stopped. A 16-bit wait and a 16-bit instruction both arrive as two bytes, low then high. During the run the word is read from instruction memory, not from the pins, and uio can be a protocol wire.
